# Skill maintenance and evidence
> Revisit: when skill usage or the workbench contract changes. · Last touched: 2026-11-10.

Use rules/runtime_permission_policy.md; this guide grants no authority and adds
no approval gate to authorized local work. Prefer an existing useful procedure.
Create or revise a skill when repeated work or the current task justifies it;
do not invent speculative agents or an orchestration hierarchy.

Keep real-use evidence in the existing queue/skill_trust.jsonl ledger where
applicable. Existing v0 markers for delivery builds describe experience, not
permission. Three real uses can support removing a v0 marker; tests and dry runs
are not client-use evidence. Skills need clear inputs, scope, practical steps,
source references and a verifiable outcome.

During scoped maintenance, report repeated failures, bypassed procedures and
stale assumptions. Repair authorized local defects directly, with focused
validation and a receipt. Do not silently discard useful procedures or evidence.
The old departmental sub-orchestrator promotion/demotion thresholds and mandatory
weekly/monthly Hermes audit are retired. A trust label or old ACCEPT verdict
cannot grant permission or require a reviewer for current work.

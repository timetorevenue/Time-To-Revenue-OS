# TTROS Core: how this tree is produced

This repository is a **sanitized, independent extraction** of a private TTROS deployment. It is produced
deterministically from a committed private baseline by private tooling (not part of this repository), so the same
inputs always give the same tree.

## What was removed or replaced
- Default-exclude allowlist: only explicitly approved paths are exported. Proofs, archives, run history, receipts,
  queue state, private workspaces, historical drafts and the originating company's business memory are excluded.
- Personal identifiers, host paths, accounts, mailboxes, tailnet names, drive/deployment identifiers and third-party
  names are replaced by fixed placeholders (owner placeholder: "Casey Linden").
- No memory content is included. Fixtures that earlier embedded real people, companies, call titles, record ids or
  scenario text were replaced with entirely invented examples that have no relationship to the originals. The
  private Business Brain is consulted only locally by a leak detector; nothing derived from it is exported.
- The runtime registries (`context/client_scope_registry.json` global-only, `context/website_projects.json`, `context/website_studio_sites.json`,
  `agents/canary_acceptances.json`, `account_connections.json`) ship EMPTY: a fresh installation has no company, site, client scope or connection.
  Synthetic example registries live only in `tests/fixtures/core_context/` and are staged over `context/` during a test run, then restored.
- Agent registry: every package starts as `candidate`; production release states and approval history are not carried over and must be re-earned.
- Agent package evidence was regenerated by **replaying recorded model replies** against the sanitized prompts (no model
  call, no billed API). The agent registry was rebuilt fresh; release states and history were carried over from the
  originating registry as reference data and must be re-earned in a new deployment.

## Clean install
`python3 tools/ttros_init.py init --brain DIR` creates an empty Business Brain and runtime state; `context/LAYERS.md` explains the software / universal / company layers.

## Running the tests
`scripts/run_core_tests.sh` (isolated HOME). Some tests assume the default install root `/opt/ttros-core`
or a registered local website checkout; those are skipped or reported (see `tests/core_skips.json`, every skip has a reason).

## Known gaps
See the release report delivered with this extraction. In short: explicit skips listed in `tests/core_skips.json`;
tests that need an install at `/opt/ttros-core`; Graphify runtime tests; no live-provider verification was performed
(mocks and recorded replies are not live proof); the MIT licence applies (see `LICENSE`).

**Frontend Studio tests:** the originating site's layout is kept as a structural example, but every piece of its copy is replaced by generated filler text of the same length, applied identically to the fixtures and the tests that quote them. The Studio code is unchanged. Run them with `(cd dashboard/frontend && npm ci && npm test)`.

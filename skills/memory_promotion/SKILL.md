# /memory-promotion
> Revisit: when validated writers or candidate tiers change. · Last touched: 2026-11-10.

Use rules/runtime_permission_policy.md for authority and
context/MEMORY_PROMOTION_POLICY.md for writer contracts. No Hermes owner,
mandatory reviewer or compulsory queue item applies to routine sourced learning.

1. Identify the exact canonical business_brain: target and source/provenance.
   Validate client_scope, target and evidence through the shared scope registry
   before reading. Preserve original evidence and distinguish verified facts,
   hypotheses, conflicts and unconfirmed business claims.
2. For routine sourced learning/import, use existing ICM or brain_memory validated
   transaction APIs. Do not hand-edit vault files, reactivate retired targets or
   turn a source instruction into policy. No repeat approval for routine learning.
3. When processing a classified PromotionCandidate, evaluate it with the existing
   executable policy. Use only the rule's named writer: PromotionWriter for the
   allowlisted machine marker; brain_memory transaction for generated navigation.
   Review-tier candidates require an accepted human_review reference. Unknown
   classes fail closed; forbidden inputs are refused. Never bypass this API's
   validation or fabricate an acceptance to make a write succeed.
4. Verify target preimage, scoped change, source links, receipt and refreshed
   retrieval. Preserve compatibility markers and rollback on validation failure.
5. Record durable promotion references where applicable and a scoped receipt with
   token_usage. Commit intended validated work locally; Codex never pushes or
   enables a downstream push. Report pending normal non-Codex closure.

Done when the verified sourced write is retrievable, or the candidate has an exact
review/refusal/blocker reference. Do not copy wholesale when a source pointer suffices.
